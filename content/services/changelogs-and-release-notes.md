## What I write

- **Release notes.** The notes for one release, with breaking changes, removals and deprecations ahead of everything else.
- **Changelogs.** The running record of every release, written so one entry still makes sense when a tool lifts it out of the page.
- **Migration notes.** What to change, in what order, when a release breaks something.

## How I write it

I read the changes and ask what each one does to a developer who upgrades. The answer to that question goes at the top of the note.

I run the release before I write about it, as I do with any product.

## What you get

You get release notes in your format for each release, and a changelog that stays readable as releases add up. If you'd rather I handle the changelog while you work on the product, that's the arrangement.
